# Graft — Project Rules (`knightb8/Graft`)

> Guidelines, architecture, and operational procedures for autonomous AI coding agents working on `knightb8/Graft`.

---

## 1. Project Mission & Identity

**Graft** is a context graph engine that indexes codebases into linked markdown nodes carrying exact file:line spans.
This repository is the **`knightb8/Graft`** fork (forked from upstream `NanoNets/context-graph-engine`).

- **Origin Remote**: `git@github.com:knightb8/Graft.git`
- **Upstream Remote**: `https://github.com/NanoNets/context-graph-engine.git`
- **Maintainer**: `knightb8`

---

## 2. Development Cycle

Work strictly follows the **BDD Chem** development cycle, vendored under `bdd_chem/` (read `bdd_chem/DEVELOPMENT_CYCLE.md`). In brief:

1. **Plan & align** before non-trivial work; write an Architectural Decision Record (ADR) under `docs/adr/` for any significant architectural change or parser integration.
2. **Specify first.** No implementation without a `.feature` file at:
   ```
   features/<domain>/<layer>/<aspect>-<counter>.feature
   ```
   Write declarative Gherkin — *what*, never *how*. See `bdd_chem/GHERKIN_PATTERNS.md`.
3. **Red → green → refactor.** Implement step definitions and production code; no unimplemented stubs remain.
4. **Close** only when every step passes, static analysis is clean, new decisions have ADRs, and the user has explicitly confirmed.

---

## 3. Project Mechanics

- **Features & Linting**:
  - `./bdd_utils.sh lint features` validates BDD layout convention.
  - `./bdd_utils.sh index features features/INDEX.md` regenerates `features/INDEX.md`.
  - `bdd_chem/` is vendored directly in the repo root.
- **Node & TypeScript Stack**:
  - `npm test` runs the test suite.
  - `npm run build` compiles TypeScript to `dist/`.
  - `npm run dev` runs continuous build watch.
  - CLI execution: `npx tsx src/cli.ts` or `npm run cli`.
- **Docs & Architecture**:
  - `docs/adr/` holds Architectural Decision Records.
  - `features/INDEX.md` is auto-generated by `./bdd_utils.sh index` (do not hand-edit).
  - `AGENTS.md` / `GEMINI.md` holds agent behavioural and workflow invariants.

## 5. Submitting Pull Requests Upstream (Zero-Pollution Cherry-Pick Workflow)

**CRITICAL**: The BDD Chem framework, `features/` directory, `bdd_utils.sh`, `AGENTS.md`, and `GEMINI.md` are local fork-specific tooling. **Under no circumstances should these files ever be included in a pull request to the upstream `NanoNets` repository.**

When a feature is ready to be contributed upstream, agents must strictly follow the Cherry-Pick PR Workflow:
1. Ensure `upstream` is fetched: `git fetch upstream`
2. Checkout a clean branch directly from upstream: `git checkout -b pr/<feature-name> upstream/main`
3. Identify the specific commits on the local feature branch that modify `src/`, `test/`, or `docs/` (excluding any BDD/Agent files).
4. Cherry-pick those specific commits onto the clean PR branch: `git cherry-pick <commit-hashes>`
5. Push the PR branch to `origin`: `git push origin pr/<feature-name>`
6. Open the Pull Request.

## 6. Graft Context & Noise Filtering Guidelines

When building or updating the codebase knowledge graph, filter out low-signal, transient, and duplicate files to preserve semantic token density and prevent graph bloat:

1. **Transient Run Logs & Checkpoints (`docs/checkpoints/`)**:
   - *Why*: Contains large migration tables, page-by-page OCR execution logs, and run reports. These change constantly and contain no architectural definitions or reusable interfaces.
2. **Brainstorming Drafts & Scratchpads (`docs/projectdocs/`, `TODO.md`)**:
   - *Why*: Informal scratch notes and unmaintained task lists. The canonical source of truth for specifications is always the BDD `.feature` files and Architectural Decision Records (`docs/adr/`).
3. **Generated Documentation Mirrors (`features/INDEX.md`)**:
   - *Why*: Auto-generated matrix produced by `./bdd_utils.sh index`. Parsing both the index and individual `.feature` files duplicates symbols and clutters graph edges.
4. **Superseded Legacy Prototypes (`src/**/*_legacy.py`)**:
   - *Why*: Early discarded prototypes (e.g., old exploratory UIs). The active production stack is defined in ADRs (FastHTML + HTMX and Textual TUI). Legacy files create phantom symbols and false dependency hubs.
5. **Scratch & Diagnostic Scripts (`scripts/`, `*generate_ocr*.py`)**:
   - *Why*: One-off scratch scripts not part of the package entry points (`pyproject.toml`) or import graph.
6. **Internal Graft Caches (`graft/.cache/`, `graft/.graph/`)**:
   - *Why*: Internal binaries and caches. Always preserve human-readable reference cards in `graft/`, but ignore internal cache trees.

**Recommended Graft Invariant**:
Prefer explicit whitelisting for high-signal directories:
`graft build --only-dir src --only-dir features --only-dir docs/adr --only-dir docs/devdocs`
Graft persists these flags in the graph fingerprint, keeping the index restricted to core source modules, BDD specs, and ADRs (saving >220k tokens per map).
